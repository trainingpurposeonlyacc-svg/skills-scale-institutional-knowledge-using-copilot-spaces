# OctoAcme Project Management Docs

Welcome to the OctoAcme project management knowledge base. This README provides links to all key project management process documents and a summary of how OctoAcme runs projects.

## Project Management Processes Overview

OctoAcme's project management approach is built on five core principles:

1. **Customer-First Delivery**: Prioritize customer value and usability in all decisions
2. **Iterative Delivery**: Release small, testable increments rather than large batches
3. **Clear Ownership**: Every project has a named Project Manager and Product Lead
4. **Data-Informed Decisions**: Measure impact and iterate based on evidence
5. **Psychological Safety**: Encourage feedback, learning, and continuous improvement

### Project Lifecycle

OctoAcme projects follow a structured five-phase lifecycle:

1. **Initiation**: Define problem statement, goals, stakeholders, and success metrics. Validate business need and obtain sponsor alignment.
2. **Planning**: Break down work into shippable increments, estimate scope, identify risks and dependencies, and create a detailed release plan.
3. **Execution & Tracking**: Build, test, and iterate using project boards. Conduct daily standups, weekly syncs, and maintain rigorous quality standards.
4. **Release & Deployment**: Deploy to production using checklist-driven processes, run smoke tests, and maintain rollback capabilities.
5. **Retrospective & Continuous Improvement**: Capture learnings, document action items, and update processes based on evidence of improvement.

### Core Roles

- **Project Manager (PM)**: Coordinates delivery, manages schedules, risks, and communications
- **Product Manager (PdM)**: Defines outcomes, prioritizes the backlog, and measures success
- **Developers**: Implement features, collaborate on design, and ensure testability
- **QA/Testing**: Validate quality and acceptance criteria
- **Stakeholders**: Provide inputs, approvals, and feedback

### Key Artifacts

- Project Charter / One-pager
- Roadmap and Release Plan
- Sprint/Iteration Backlog
- Acceptance Criteria & Definition of Done
- Risk Register
- Retrospective notes and action items
